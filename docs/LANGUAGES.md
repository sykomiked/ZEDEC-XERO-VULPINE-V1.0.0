# Languages in ZXV

The kernel's language module is `kernel/src/i18n/`. It holds four things:

- a registry of every CLDR locale;
- the UI message catalogs;
- number, currency and date formatting that uses integers only;
- UTF-8 handling that keeps graphemes whole.

Like the rest of the kernel it is freestanding C11. It uses no libc, no
floating point, no allocation and no 64-bit division.

**Translation status.** English is the only source text. Every other
handwritten string is **machine translation that needs native review**, and
the code reports that status with every string it returns, so the UI can say
so. No native speaker has reviewed any catalog yet. No string is marked
reviewed, and the tests check that none is.

## What is in the module

| File | What it does |
|---|---|
| `i18n.h` | Public API: registry, plurals, messages, formatting, dates, UTF-8. |
| `i18n_internal.h` | Table layouts shared by the code and the generated tables. |
| `i18n_text.c` | UTF-8 validator, decoder and sanitizer; grapheme clusters; truncation; `{n}` message formatting with bidi isolation. |
| `i18n_locale.c` | Registry, tag resolution, CLDR plural rules, message lookup with fallback. |
| `i18n_format.c` | Integer-exact decimal, percent, currency and Gregorian date formatting. |
| `i18n_enochian.h/.c` | The edge between the Enochian core and the operator's language (see below). |
| `gen_i18n_tables.py` | Generator: CLDR JSON and `catalog/*.msg` in, the three files below out. |
| `i18n_tables.c`, `i18n_catalog.c`, `i18n_msgid.h` | Generated tables. Do not edit them by hand. |
| `catalog/<tag>.msg` | Message catalogs, one per language. |
| `test_i18n.c`, `test_i18n_enochian.c`, `test_i18n_cov.c` | Host tests. |

**Data sources:**

- **Unicode CLDR 48.2.0** (the `cldr-json` packages, published 2026-03-18;
  Unicode License v3). This supplies locales, plural rules, number symbols and
  patterns, currency symbols and digits, month and day names, date patterns,
  relative-time strings, likely subtags, parent locales, exemplar characters
  and coverage levels.
- **Unicode 15.1** character properties, used for the grapheme Extend table.

## Tag resolution and fallback

`i18n_locale_resolve()` turns a tag into a locale in seven steps:

1. Accept any case, and `_` as well as `-`.
2. Drop extensions and private-use subtags (`en-US-u-ca-gregory` becomes `en`).
3. Apply CLDR language aliases (`tl` becomes `fil`, `iw` becomes `he`, `in`
   becomes `id`, `sh` becomes `sr-Latn`).
4. Use CLDR likely subtags to pick the script a region implies (`zh-TW` gives
   `zh-Hant`, `sr-ME` gives `sr-Latn-ME`, `uz-AF` gives `uz-Arab`).
5. Remove subtags from the end until a tag matches.
6. Fall back to `en` if nothing matches.
7. Treat `pt-BR` as `pt`, because CLDR's `pt` is Brazilian Portuguese.

Message lookup walks the CLDR parent chain, then English. For example,
`sw-KE` falls back to `sw`, then `en`, and `pt-AO` to `pt-PT`, `pt`, then `en`.
CLDR's non-likely-script rule applies, so `ff-Adlm` has `root` as its parent,
not `ff`.

`i18n_msg()` reports four things in `i18n_msg_info_t` alongside the text:

- which locale the text came from;
- its review status;
- its note;
- whether it fell back.

A plural message whose form came from a fallback language re-chooses the form
using that language's rules.

## Review status

Every catalog line declares its status, and the generator rejects a catalog
whose status is missing or malformed.

| Status | Meaning | Who may use it |
|---|---|---|
| `source` | The original English text. | `en.msg` only |
| `machine` | Machine translation, **needs native review**. | Every handwritten non-English line today |
| `cldr:<path>` | Taken from CLDR (e.g. relative-time "{0} minutes ago"). | Generated by the tool, not hand-written |
| `native:<reviewer>:<YYYY-MM-DD>` | Reviewed and accepted by a named native speaker. | Only after a real review (see below) |

The UI should show a "machine translation, not yet reviewed" notice whenever a
string's status is `machine`. The message `LANG_REVIEW_NOTICE` says this. Full
catalogs translate it; other languages fall back to the English notice.

## Status tiers

| Tier | What it means | Languages |
|---|---|---|
| **Full** | Every UI id (the hand-written set from the mockups), machine-translated. | `ar` `es` `fr` `la` `pt` `ru` `sa` `sa-Latn` `sw` `zh` `zh-Hant` |
| **Core** | The 16 core ids: navigation, Send/Cancel/Reply, Confirm payment, Amount, Offline/Online, Connected, Language, a generic error. Everything else falls back to English. | 110 languages (see the table) |
| **Subset** | Fewer than 16 ids, where I could not produce more with confidence. Often just the word for "Language". | `aii` `arc-Hebr` `ay` `bo` `cv` `dv` `fo` `gn` `haw` `iu` `ln` `mi` `mn-Mong` `nd` `nr` `nv` `qu` `rm` `se` `sm` `ss` `syr` `to` `ts` `ve` |
| **CLDR only** | No catalog. Numbers, dates, plurals and CLDR relative-time strings are localized; UI text is English. | Every other CLDR locale |
| **Root only** | Not in CLDR and no catalog. Formats are CLDR root (dates like `2026 M10 9`), and the UI is English. | `arc` (Imperial Aramaic), `crs`, `kg`, `kr`, `nah`, `rom`, `swb`, `yua` |

`sa-Latn` (Sanskrit in IAST) is not in CLDR. It is derived from `sa` by a
Devanagari-to-IAST transliteration, for both the CLDR data and the catalog.
Its note is `translit:sa`, and its status follows its `sa` source line.

Full languages are those of the African Union (see below), the UN official
languages, Sanskrit, Latin and Kiswahili. Core languages are, in principle,
every language with more than about 10 million speakers, plus Cyrillic-script
languages and several regional and Indigenous languages. The subset tier is
deliberately small: a wrong UI string in a language with few speakers costs
more than an English fallback.

### Notes on particular languages

- **Sanskrit (`sa`, `sa-Latn`).**
  - It is a full UI language in Devanagari, with IAST Latin derived from it.
  - Technical terms are Neo-Sanskrit coinages, and the catalog header says so.
  - CLDR has no plural rules for `sa`, so plural messages carry only `other`.
- **Latin (`la`).**
  - Latin is a full UI language, using Neo-Latin technical vocabulary
    (*rete*, *interrete*, *servitor*).
  - CLDR has no plural rules for `la`, so plural messages carry `other`, in
    the grammatical plural.
- **Aramaic.**
  - `syr` (Syriac, Syrc script, RTL) is a CLDR locale with a subset catalog.
  - `aii` (Assyrian Neo-Aramaic, Syrc) has a subset catalog.
  - `arc-Hebr` (Aramaic in square Hebrew script) has a subset catalog.
  - `arc` (Imperial Aramaic, Armi script, U+10840 block) has no catalog and
    uses root formats. Its autonym is ours, not CLDR's.
  - None of the Aramaic UI text is reviewed.
- **Cyrillic.**
  - Core catalogs: `ru` (full), `uk` `be` `bg` `sr` `sr-Latn` `mk` `kk` `ky`
    `tg` `mn` `tt` `ba`.
  - Subset catalog: `cv`.
  - `cu` (Church Slavonic) is CLDR-only. Its exemplars need combining marks
    and Cyrillic Extended-A, which the font module does not classify.
- **Kanuri, Kongo, Seychellois Creole, Comorian, Aymara, Nahuatl, Yucatec Maya,
  Samoan, Romani, Aramaic and Assyrian Neo-Aramaic** have no CLDR locale. Their
  registry entries use our English names, are flagged (`I18N_LF_CLDR` is
  clear), and use root formats.
- **Plain `ar`** uses Latin digits in CLDR 48. `ar-EG`, `ar-SA` and other
  regional locales use Arabic-Indic digits and the ALM mark before a minus.

## The African Union's official languages

**What is in force.** Article 25 of the Constitutive Act (2000) names four
working languages: Arabic, English, French and Portuguese. The Act says "if
possible, African languages".

**The 2003 Protocol.** The Protocol on Amendments to the Constitutive Act (2003)
would amend Article 25 to read "Arabic, English, French, Portuguese, Spanish,
Kiswahili and any other African language", which adds Spanish and Kiswahili.
Article 13 says the Protocol enters into force once two thirds of member states
have ratified it. Per AfricanLII, about 30 states have ratified, against the
37 needed, so the amendment appears **not yet in force**.

**The 2022 Assembly decision.** Assembly decision **Assembly/AU/Dec.832(XXXV)**
(February 2022), building on Dec.796(XXXIV) (2021), approved **Kiswahili as a
working language of the AU** and a language of wider communication. It set
operationalisation for July 2023, and Tanzania pledged USD 250,000 towards it.

**What this means for ZXV.** No language has been formally added by an amended
Constitutive Act in force. Kiswahili has been added as a working language by
Assembly decision. This module treats six languages as the AU set, and all six
have full catalogs:

- Arabic
- English
- French
- Portuguese
- Spanish
- Kiswahili

Sources:

- Protocol text: <https://www.jus.uio.no/english/services/library/treaties/14/14-03/protocol-amendments-au.xml>
- Ratification table: <https://africanlii.org/akn/aa-au/act/protocol/2003/amendments-to-the-constitutive-act-of-the-african-union>
- Decision 832: <https://africanlii.org/akn/aa-au/act/decision/2022/832>

The registry records, for each locale, the AU member states that use it
(`i18n_locale_au_states()`, from CLDR territory language data).

## Formatting

- **Numbers.** CLDR patterns are precompiled into affixes plus grouping sizes
  (primary, secondary and minimum grouping, kept separately for decimal,
  percent, currency and alphabetic currency). Digits come from the locale's
  numbering system: Arabic-Indic, Extended Arabic-Indic, Devanagari, Bengali,
  N'Ko, Adlam, Myanmar and others (Ethiopic numerals are not a CLDR numbering
  system default, so Amharic uses Latin digits). Values are integers
  with an exponent (`i18n_fmt_decimal(l, 12345, 2)` gives 123.45). Bidi marks
  (LRM, ALM, RLM) are kept as CLDR specifies.
- **Currency.** The amount is in minor units, with the exponent from ISO 4217
  or CLDR currency data (`i18n_currency_digits`). The symbol can be standard,
  narrow or the ISO code. CLDR `currencySpacing` and the `alphaNextToNumber`
  pattern are applied, so the output is "US$ 5" or "5 $US" as each locale
  writes it.
- **Dates.** The calendar is proleptic Gregorian only. Day counts are
  converted with Hinnant's algorithm, using int32 floor division and no 64-bit
  division. The styles are CLDR full, long, medium and short, with real month
  and day names where CLDR has them (otherwise `M10`). Years before 1 CE return
  -1. Other calendars are not implemented: Ethiopian, Islamic, Hebrew, Persian
  and Buddhist.
- **Plurals.** CLDR cardinal rules are interpreted in C, with operands n, i, v,
  w, f and t. `i18n_plural_decimal()` handles visible fraction digits, as in
  "1.0 hours" in English.
- **Message arguments.** `i18n_format_msg()` substitutes `{0}` to `{9}`. It
  wraps an argument in FSI…PDI (U+2068/U+2069) when the locale is RTL or the
  argument contains strong RTL text. This means an Arabic name inside English,
  or a Latin amount inside Arabic, cannot reorder its surroundings.

## UTF-8 and graphemes

- `i18n_utf8_valid()` rejects overlongs, surrogates, values above U+10FFFF and
  truncated sequences.
- `i18n_utf8_sanitize()` replaces bad bytes with U+FFFD.
- Grapheme clusters follow a simplified UAX #29:
  - CR LF;
  - Extend (Mn, Me, Mc, ZWJ, emoji modifiers, tags);
  - regional-indicator pairs;
  - Hangul L/V/T syllables;
  - emoji ZWJ sequences (GB11);
  - Indic virama conjuncts (GB9c);
  - a short Prepend list.

  It is not the full Unicode table. In particular, GB9c applies to the main
  Indic viramas, not every InCB linker.
- `i18n_truncate()` and `i18n_truncate_ellipsis()` never split a cluster.
- Every bounded writer cuts back to a cluster boundary on overflow and returns
  -1. It keeps the last cluster only when the text that did not fit would have
  started a new cluster, so no accent, tone mark or conjunct is lost.

The tests round-trip Ge'ez (Amharic) text, Arabic-Indic digits, RTL marks,
N'Ko, Adlam and Devanagari conjuncts.

## Fonts: what `kernel/src/font` cannot show

The font module has three limits:

- It ships only a builtin 8x8 ASCII diagnostic font. There are no font files
  in the repository.
- Its TrueType reader (`truetype.c`) handles only cmap format 4, which covers
  the BMP. It cannot reach supplementary-plane scripts such as Adlam
  (U+1E900), Imperial Aramaic (U+10840), Hanifi Rohingya, Chakma or Deseret.
  It also declines composite glyphs and does no mark positioning.
- `script.c` (`font_script_of()`) has range gaps. Code points in these ranges
  come back as `SCRIPT_UNKNOWN`, so they cannot be routed to any font:
  - IPA (U+0250–02AF), which covers ɛ ɔ ɓ ɗ for many West African languages;
  - combining diacritics (U+0300–036F), needed for Yoruba, Vietnamese and
    polytonic Greek;
  - Latin Extended Additional (U+1E00–1EFF), needed for Vietnamese and Yoruba;
  - Ethiopic Supplement and Extended;
  - Arabic Extended-A and presentation forms;
  - currency symbols (U+20A0–20CF): ₦ ₵ ₹ €;
  - Latin-1 punctuation (U+00A1–00BF): « » § ·;
  - Latin Extended-C and D;
  - several whole scripts, including Gujarati, Kannada, Telugu, Malayalam,
    Oriya, Gurmukhi, Sinhala, Khmer, Lao, Myanmar, Tibetan, Mongolian, Yi,
    Cherokee, Coptic, Ol Chiki, Meetei Mayek and Osage.

`test_i18n_cov` runs `font_script_of()` over every code point each locale
needs, from CLDR exemplars, punctuation and digits, and prints a report. On the

## Complex shaping

These scripts cannot be drawn correctly glyph by glyph:

| Script | Why |
|---|---|
| Arabic, Syriac, N'Ko, Adlam, Mongolian, Hanifi Rohingya | Cursive joining (initial, medial, final and isolated forms), mark positioning; Mongolian is also written vertically |
| Devanagari, Bengali, Gurmukhi, Gujarati, Oriya, Tamil, Telugu, Kannada, Malayalam, Sinhala | Conjuncts, reordering of pre-base vowel signs and reph, mark stacking |
| Thai, Lao | Mark stacking (tone marks above vowels); line breaking needs a dictionary |
| Khmer, Myanmar | Subscript consonants (coeng / medial), reordering; dictionary line breaking |
| Tibetan | Vertical consonant stacks |
| Ge'ez, Tifinagh, Vai, Cherokee, Han, Kana, Hangul (precomposed) | Simple: one glyph per code point |
| Latin, Cyrillic, Greek with combining marks | Mark positioning (or precomposed NFC where it exists) |

The kernel does not build a shaper, and this module does not include one. The
host app must shape text with **HarfBuzz** (MIT licence) or the platform's
equivalent (Core Text, DirectWrite, Android's Minikin). The kernel's job ends
at what it already gives a shaper:

- valid UTF-8;
- grapheme-safe truncation;
- script runs from `font_script_itemize()`;
- the bidi isolates added by `i18n_format_msg()`.

Mongolian vertical layout and the full Unicode Bidirectional Algorithm also
belong in the host.

## The Enochian core and the operator's language

The swarm processes and stores in Enochian, and translates only at the edge
(`kernel/src/swarm/swarm_enochian.h`, E8). This module keeps to that rule in
three ways:

- The core holds **message ids** (`i18n_msgid_t`, from `i18n_msgid.h`) and
  their stable keys (`i18n_msg_key(I18N_PAY_CONFIRM_TITLE)` returns
  `"PAY_CONFIRM_TITLE"`), never translated text.
- The operator language installed in a `swarm_lang_table_t` chooses the
  catalog only when text is shown: `i18n_edge_locale(t)` and
  `i18n_edge_msg(t, id, &info)`.
- Changing the operator language changes nothing the core stores.
  `swarm_lang_core()` stays `"enochian"`, and every id and key stays the same.
  `test_i18n_enochian` checks this when switching between en, sa, sw and kr.

`i18n_enochian_render(text, len, I18N_EN_DEVANAGARI | I18N_EN_IAST, out, cap)`
shows an Enochian letter string in Devanagari or IAST. It renders word by word
through `swarm_en_sanskrit()` and `swarm_en_iast()`, keeps one space between
words, and drops characters outside the alphabet. This module only links
against `swarm_enochian.c` and does not change it.

## How to add a language

1. Check that the locale exists: `i18n_locale_find("xx")`. Every CLDR locale
   is already in the registry. For a language CLDR lacks, add it to `EXTRA` in
   `gen_i18n_tables.py`, giving its English name, autonym, script and a note.
2. Copy the header of an existing catalog, write `catalog/<tag>.msg`, and give
   it a description. Each line has the form:

   ```
   ID|category|status|text
   ```

   - `ID` is one of the ids in `en.msg`.
   - `category` is `-` for a plain message, or a CLDR plural category (`zero`
     `one` `two` `few` `many` `other`) for a plural message. A plural message
     needs exactly the categories the locale's CLDR rules define.
   - `status` is `machine` unless a native speaker has reviewed the line (see
     below).
   - `text` must be NFC, must not be empty, and must use exactly the same `{n}`
     placeholders as the English.
   - Leave out any id you cannot translate well. It falls back to English, and
     the UI says so.
3. Regenerate from `kernel/src/i18n/`:

   ```sh
   python3 -I gen_i18n_tables.py <cldr-json dir> --docs ../../../docs/LANGUAGES.md
   ```

   `<cldr-json dir>` holds the unpacked npm packages `cldr-core`,
   `cldr-numbers-full`, `cldr-dates-full`, `cldr-localenames-full` and
   `cldr-misc-full`, version 48.2.0, each under `<pkg>/package/`. The generator
   validates every catalog and stops with a message if one is wrong. It also
   rewrites the table below.
4. Run the three tests (see `kernel/Makefile`, target `verify-all`).

To add a UI string, add the id to `en.msg` with status `source`, then
regenerate. `i18n_msgid.h` gets a new `I18N_<ID>` constant. Ids are sorted, so
code must use the constant and never a number.

## How native review works

1. A native speaker reads the catalog in context, ideally in the running UI
   with the review notice visible.
2. For each line they accept, the status changes from `machine` to
   `native:<reviewer>:<YYYY-MM-DD>`. `<reviewer>` is a name or handle the
   project can contact, and the date is the day of review. For example:

   ```
   BTN_SEND|-|native:amina-o:2026-11-02|Tuma
   ```

3. A corrected line gets the corrected text and the native status in the same
   change.
4. The reviewer changes the catalog header from "MACHINE translation" to say
   who reviewed it and when, once every line is reviewed.
5. The change is reviewed like code, and the commit names the reviewer.
6. Only `native:` lines count as reviewed. `i18n_msg()` then returns
   `I18N_REVIEW_NATIVE`, and the UI can drop the notice for that string.
   Nothing else can produce that status.

Until a language has a reviewer, its text stays `machine`. Do not change a
status to `native:` for a review that did not happen.
