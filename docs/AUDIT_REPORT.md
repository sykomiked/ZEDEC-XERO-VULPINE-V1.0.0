# ZXV Audit Report (2026-10-09/10)

A full audit of the repository: all 210 modules under `kernel/src`, the Mac app, the bare-metal
kernels, bindings, mobile, build and CI, the docs, and every requirement the owner has given.
Each module's tests were built and run (gcc 11, as in CI), parsers that read outside input were
fuzzed under AddressSanitizer and UBSan, and claims in comments and docs were checked against the
code. Every finding below was reproduced or confirmed by reading the code. What each module does is
in [SYSTEM_REFERENCE.md](SYSTEM_REFERENCE.md).

## Result

After the fixes, `make -C kernel verify-all` passes in a clean checkout (3,984 passing checks;
40 new or repaired test recipes were added to it). GitHub CodeQL was added; its alerts were fixed.

| Severity | Fixed | Not fixed |
|---|---|---|
| CRIT (security hole, money or ledger wrong, data loss) | 15 | 0 |
| HIGH (wrong result, crash or overflow on bad input) | 37 | 3 |
| MED (misleading claim, missing test, stub reporting success) | 50 | 74 |
| LOW (style, dead code) | 15 | 53 |
| **Total** | **117** | **130** |

Plus 24 CodeQL alerts (integer overflow before widening, snprintf length, narrow loop counters):
all fixed, except one in the vendored HQC reference code, which cannot overflow and is now
filtered out because vendored code stays identical to its upstream release.

### The 15 critical problems (all fixed)

- **loader/abupdate**: an old, validly signed v1 package could replace an active v2 package and
  skip the anti-rollback floor.
- **community_chest**: the revenue split paid out 105% of the price at an 85% developer share;
  voucher purchases debited the buyer and credited nobody.
- **battering_ram**: payout attestations were checked against a key carried inside the attestation,
  so anyone could self-sign and release the pool.
- **count_house**: the money supply counter could wrap to zero and pass the collateral check.
- **finance/rails**: a negative sale credited the card and refunds were uncapped (both minted money).
- **finance/triple_ledger**: vouchers could be redeemed into someone else's account; transfers were
  not atomic, and provenance/externality legs leaked into balances.
- **fs**: transaction snapshots were never released; after 32 transactions a rollback lost data.
- **fat32**: a crafted disk image overflowed a stack buffer on mount.
- **porter_house**: closing a port failed open when the seal table was full.
- **rmag**: budget arithmetic wrapped, and negative amounts refunded budget.
- **sdk_bridge**: a language context was cast to a different struct, so capability checks read the
  wrong fields.
- **sutra**: payment coverage used floating point and approved underpayments.
- **vino**: minting left no trace in any of the three ledgers.

### Still open: the three HIGH items

- **bootlegger** handshake: the signature covers no nonce (replayable) and the ML-KEM key is not
  bound to the identity (man-in-the-middle). Fix: both peers sign a transcript of identity,
  ephemeral key and the peer's challenge. This is a protocol change.
- **fs** replicate/recover only set flags, so "recovery" restores an empty node. Needs a design.
- **CI** boot checks: now fixed for arm64 and x86_64 (they must reach `[BOOT_OK]`); riscv64,
  riscv32 and arm32 report a warning instead, because they have not yet been seen to reach
  `[BOOT_OK]`.

### Decisions only the owner can make

- Update signatures (`update`, `broker`) cover only the content ID, so version numbers are unsigned.
  Signing the version and dependencies changes the update format.
- Fibonacci-only coin denominations: `vino_mint` accepts any amount today.
- Fee waterfall 34% / 3.3% / 3% versus the φ% tithe: only the tithe is implemented.
- IPNS name versus the fixed bucket CID for updates.
- What "STA" stands for (the tensor engine models it as an axial core).
- Where model weights are hosted, and the oldest Intel Mac to support.
- Three tracked build outputs could be removed from git: `a.out`, `binaries/vovina_shakina.bin.zip`,
  `kernel/third_party/ed25519/*.dll`.

## Integration gaps (working parts not yet joined up)

See the platform findings below for the wiring each needs. The main ones: the swarm budget does not
drive the model's tokens; GGUF Q5_0/Q5_1 weights are not read, so the Q4_K_M Qwen2.5-0.5B file the
mobile docs recommend is refused; swarm and tensor are in no kernel image; the Mac app has no Vinea,
IPFS or socket glue (so no offline/LAN/online modes yet) and does not link notifications, speech or
the update checker; ehop is not wired into Vinea (payload and per-fragment overhead limits); capital
forms are ordered four different ways across modules.

#### Open questions still unanswered by the owner

1. **Fibonacci-only coin denominations.** `kernel/src/vino_stores` has a Fibonacci ladder, but `vino_mint` accepts any value and `pay` amounts are free integers. Must every VFV coin be a Fibonacci rung, or is the ladder only for minted vouchers?
2. **Fee waterfall 34% / 3.3% / 3% versus the phi tithe.** No code implements a 34/3.3/3 waterfall (grep finds none); `pay_tithe` implements the phi% tithe only. Which applies, and if both, in what order?
3. **IPNS versus a fixed CID for the update bucket.** `zx_upcheck` supports both; the built-in entry is the fixed CID `bafybeiczsscdsbs7ffqz55asqdf3smv6klcw3gofszvwlyarci47bgf354`, which can never change. The owner has not chosen an IPNS name or confirmed the fixed CID.
4. **Meaning of "STA"** (the core coil in the torus hole). Modelled in `zt.h` as an axial core of F(b-1) slots; the owner never said what STA stands for.
5. Also still open from the memory notes: weight hosting (where model files live), the oldest Intel Mac to support, and whether the user's VINO Sovereign Standard resolution class should stay 811.
