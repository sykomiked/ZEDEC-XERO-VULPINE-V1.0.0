# Test coverage

This file is generated by `fuzz/tools/coverage.sh`. Regenerate it with
`make -C fuzz coverage`; CI runs the same script in the `coverage` job.

## How it is measured

The measurement uses clang 18 source-based coverage (`-fprofile-instr-generate
-fcoverage-mapping -fcoverage-mcdc`) of two things:

* the whole host test suite: `make -C kernel verify-all`, with every hosted test program
  rebuilt with the coverage flags through `fuzz/tools/san-cc`;
* a replay of the committed fuzz corpora (`fuzz/corpus`).

`llvm-profdata` merges the raw profiles. `llvm-cov export` then summarises them over all
the instrumented programs, and `fuzz/tools/coverage_table.py` groups the files by module.

The table counts only the code under test. Test drivers (`test_*.c`), the fuzz harnesses,
vendored `third_party` code and system headers are left out.

**A module appears in the table only if some test program links it.** Modules that no
test links are listed after the table. They are not in the totals, so for them the
coverage is effectively zero.

Columns:

* Lines and Branches: llvm-cov line and branch coverage.
* Functions: functions entered at least once.
* MC/DC: clang 18's Modified Condition/Decision Coverage, measured by the tool. The count
  is of conditions in decisions that clang can instrument for MC/DC (clang 18 handles
  decisions of up to 6 conditions). The figure is the share of those conditions shown
  to independently affect their decision's outcome.

These are measured numbers. They are not a certification target and imply no compliance
claim.
