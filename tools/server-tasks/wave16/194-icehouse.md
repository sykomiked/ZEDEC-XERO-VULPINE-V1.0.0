What it does: freezes snapshots of systems and data into cold archives (`backup.run`, `backup.list`, `backup.verify`) and thaws them on demand (`backup.restore`), within the free space `sys.disk` reports. zxvd has no method for an archive codec (as Hamper reports): use only existing methods; list what's missing in your report.
Uses: `use keepsake 1` (`keepsake.removed`, `keepsake.keep_ok`); `use cellar 1` (used share, "safe to repair"); `use seedbank 1` (CID check, size limits); `use hamper 1` (entries in bounds, path safe, expansion guard, totals). Call these composed entries; do not re-implement them.
Logic (critical, new decisions only): "thawed copy trusted" (size and content id equal the recorded ones) in Ada as Eve + APL as KRON witnessed; compression ratio x100 (packed x 10000 / unpacked) in FORTRAN as Trebago + APL as KRON witnessed; archive catalogue (archive number, bytes, refused on overflow) in COBOL as Sutra; block arrays in APL as KRON; snapshot tree in MUMPS as MYRA.
BOTH test: a thawed file's content id is 77 and the recorded one 78: it is BOTH and quarantined, not trusted.
Tests: as the spec, plus a compose test (the app composes against a registry holding its parts, and every part entry it calls resolves) and the BOTH test above.
needs: backup, fs.read, fs.write, sys.read.
