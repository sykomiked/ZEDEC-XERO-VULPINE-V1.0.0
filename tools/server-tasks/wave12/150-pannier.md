Depends on: wave 2 (026 rookery, 029 trellis, 031 pollen), wave 7 (090 caravan).

What it does: carries messages and data parcels store-and-forward between peers (`net.peers`, `peer.status`), cut into freights that survive lost packets (`freight.pack`, `freight.unpack`), with the queue in the Hoard (`files.read`, `files.write`). zxvd has no method for a store-and-forward relay queue in the daemon: use only existing methods; list what's missing in your report.
Uses: `use rookery 1` ("may this be sent", size limits, folder and thread index); `use trellis 1` (peers per state, peer record); `use pollen 1` ("fits on the receiver", chunk plan); `use caravan 1` (shipment records, the tracking pattern for a parcel). Call these composed entries; do not re-implement them.
Logic (critical, new decisions only): "send now" = peer active AND parcel within size AND attempt at most the retry limit, in Ada as Eve + APL as KRON witnessed; retry limits (at most 16 attempts, back-off capped at 3600 s) in Ada as Eve; delivery receipts (sequence per peer strictly rising, refused on reuse or overflow) in COBOL as Sutra + APL as KRON witnessed; route timing (expected hours as the sum of hop times) exact in FORTRAN as Trebago; the queue as a bounded ring (head - tail >= capacity is backpressure, oldest first) in APL as KRON; parcel tree in MUMPS as MYRA.
BOTH test: parcel 9 has a signed receipt (sequence 5) and a hop report saying lost: the parcel is BOTH, it is neither re-sent nor closed until a witness (a second receipt or the recipient) confirms.
Tests: as the spec, plus a compose test (the app composes against a registry holding its parts, and every part entry it calls resolves) and the BOTH test above.
needs: peers, net, fs.read, fs.write, notify.
