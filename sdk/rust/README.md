# ZXV Rust SDK

Safe Rust bindings to `libzxv`, the stable C ABI of the ZXV platform
(`sdk/libzxv/include/zxv_api.h`, ABI 1.6). Two crates:

| Crate | What it is |
|---|---|
| `zxv-sys` | Raw `unsafe` bindings, generated by bindgen and checked in (`src/bindings.rs`), so a normal build needs no libclang. |
| `zxv` | The safe API you use. |

## Install

Build `libzxv` first (`make -C sdk/libzxv`), then depend on the crate:

```toml
[dependencies]
zxv = { path = "sdk/rust/zxv" }            # dynamic libzxv.so
# zxv = { path = "sdk/rust/zxv", features = ["static"] }   # link libzxv.a
```

`zxv-sys` finds the library in `ZXV_LIB_DIR`, else in `sdk/libzxv/build`.
With the default dynamic link your binary needs `libzxv.so` at run time:
use `LD_LIBRARY_PATH`, install it on the system path, add an rpath in your
own `build.rs` (`cargo:rustc-link-arg=-Wl,-rpath,<dir>`), or use the
`static` feature. This crate's own tests and examples get an rpath
automatically.

Regenerate the raw bindings after a header change (needs libclang):

```sh
LIBCLANG_PATH=/usr/lib/llvm-18/lib cargo build -p zxv-sys --features regenerate
```

## Quickstart

```rust
use zxv::{AccountKind, Caps, Context, Ledger};

fn main() -> zxv::Result<()> {
    let ctx = Context::new()?;                                  // one platform instance
    let root = ctx.root_capability(1, None, Caps::ALL)?;        // what you may do
    ctx.enable_currency_cap(&root, "NGN")?;
    let ledger = Ledger::new(&root);
    let bank = ledger.open_account("bank", "NGN", AccountKind::Issuer)?;
    let alice = ledger.open_account("alice", "NGN", AccountKind::Holder)?;
    ledger.post(bank, alice, 12_550, "NGN", "E2E-0001")?;     // exact minor units
    println!("{}", ledger.balance(alice)?.equity);              // 12550
    Ok(())
}
```

## Concepts in Rust terms

**Handles and lifetimes.** Every C handle is a Rust struct that frees it in
`Drop`. Children borrow their parents: `Capability<'c>` borrows its
`Context` (and an attenuated capability borrows its parent), `Session<'a>`
borrows its `Model`, its `Capability` and any bound `Budget`,
`DeferredEvent` borrows its `PhaseClock`. The C rule "destroy a child
before its parent" (R6) is enforced by the borrow checker; writing it the
other way round does not compile.

**Threads.** `Context`, `Capability`, `Model`, `Budgets`, `PhaseClock`,
`Swarm` and `Attestations` are `Send + Sync` (the C objects are
mutex-protected or immutable). `Session` and `iso20022::Message` are `Send`
but not `Sync`: one thread at a time, as the C ABI requires.

**Errors.** Every fallible call returns `zxv::Result<T>`. `zxv::Error` is an
enum by status class: `Usage` (your bug), `Refused(RefusedKind, _)` (handle
it: `CapabilityDenied`, `BudgetExhausted`, `InsufficientFunds`,
`VerificationFailed`, `NotImplemented`, ...), `Fatal` and `System`. Each
carries `status()`, `name()` and `detail()` (the library's last-error text;
never branch on it).

**Fail closed.** A FATAL status (a broken ledger invariant, or
`Context::halt`) halts the context in C: every later call returns
`ZXV_E_POISONED`. The Rust `Context` is also marked poisoned, and every
handle derived from it returns `Error::Fatal` without reaching the library.
`Context::with_fatal_policy(FatalPolicy::Abort)` instead prints the error
and calls `std::process::abort()`: the only form that cannot be caught.

**Capabilities.** Objects that make gated calls (`Ledger`, `Budgets`,
`PhaseClock`, `Swarm`, `Attestations`, `Ed25519`, `MlDsa87`, `MlKem1024`,
`StateChannel`, `Session`) hold a `&Capability` and pass it on every call.
Narrow with `cap.attenuate(Caps::LEDGER_READ)`; `revoke()` revokes all
descendants; an attestation other than `Truth::True` blocks the cap.

**Exact numbers.** No public function takes `f32`/`f64` except
`Rational::from_f64_exact`, which returns the double's exact value
(`0.1` is `3602879701896397/36028797018963968`) and rejects NaN/infinity.
`Rational` is a `Copy` value with `checked_add/sub/mul/div` returning
`Result`, exact `Ord`, `FromStr` (`"12.75"`, `"3/4"`) and `Display`. There
are no `+ - * /` operators, so overflow is always a `Result`. Sampling
parameters are `Rational`s, converted to Q16.16 by the library.

**Four-valued logic.** `Truth` is `Neither`, `True`, `False`, `Both`
(numbered 0..3 as the kernel numbers them). There is no `From<Truth> for
bool`; use `is_certainly_true()`, `to_bool(on_both, on_neither)` or
`require_true()`.

**Secrets.** `SecretKey` holds secret keys and shared secrets in one heap
allocation wiped with `zxv_secure_zero` on drop; `Debug` is redacted; the
only way out is `export_bytes_unsafe()`.

**Async.** `Budget::consume_async(amount)` returns a plain
`std::future::Future` that consumes now or waits until the budget is
replenished (a `release` or a larger `set_limit` through this SDK), then
retries; it fails immediately on an invalid amount. `PhaseClock::defer(tick)`
returns a `DeferredEvent` you `.await` (`IntoFuture`) or wait on with
`.cleared()`. They need no particular runtime: tokio, async-std,
`futures::executor::block_on`, or your own. Cancel by dropping the
future; add timeouts with your runtime. Drive the clock manually with
`advance(n)` or in real time with `run_realtime(ticks_per_second, &stop)` on
a thread you own.

**Generation.** `Session::generate` (all at once), `generate_with` (a
callback per token; return `false` to stop) and `stream` (an `Iterator` of
tokens inside a closure; dropping it stops generation). The same seed and
inputs give the same tokens on every machine.

## Capabilities on every gated call (ABI 1.2)

Every gated operation takes a `Capability`, and the SDK calls the
capability-gated `zxv_*_cap` form of the C ABI:

| Call | Needs |
|---|---|
| `Context::enable_currency_cap`, `enable_currency_with_minor_cap`, `register_private_currency_cap` | `LEDGER_POST` |
| `Ledger::open_account`, `post` | `LEDGER_POST` |
| `Ledger::balance`, `account`, `account_count`, `journal`; `Capability::new_message` | `LEDGER_READ` |
| `Budgets::new`, `PhaseClock::new`, `Attestations::new`, `Swarm::new` | `BUDGET`, `PHASE`, `ATTEST`, `SWARM` |

A capability of another context is refused with `ZXV_E_CAP`
(`is_capability_denied()`). A message borrows the capability it was made
with and the library re-checks it on every call. The 1.0 forms
`Context::enable_currency`, `enable_currency_with_minor`,
`register_private_currency` and `new_message` still work but are
`#[deprecated(since = "1.2.0")]`.

## The hexagram tag (ABI 1.3)

A `Hexagram` tags one unit of work with a four-valued base, the polarity
of its evidence (entropic, neutral, forbidden, negentropic) and its phase
(potential -> emerging -> manifest -> dissolving), packed into one byte
0..63. Its action is proceed, wait, refuse, escalate or rollback. Every rule
comes from libzxv and is tested against `vectors.json` key `hex`.
Forbidden is absorbing, a phase moves one step at a time, and the base is
**not** numbered like `Truth` (TRUE is base 3 but Truth 1): convert only
with the explicit `to_truth()` / `Hexagram::from_truth(...)`. Combining BOTH with NEITHER follows
the `Truth` tables (AND gives NEITHER, OR gives BOTH); those two results
are pending an owner decision. A `QuarantineLog` (needs the ATTEST
capability) records forbidden work in a SHA-256 hash chain; when it is
full, append is refused with `ZXV_E_CAPACITY` and you must halt the
context. See [ABI.md, Changes in 1.3](../docs/ABI.md#changes-in-13).

```rust
use zxv::{HexAction, HexBase, HexPhase, HexPolarity, Hexagram, QuarantineLog};

let h = Hexagram::new(HexBase::True, HexPolarity::Negentropic, HexPhase::Potential);
assert_eq!(h.action(), HexAction::Proceed);
let h = h.advance();                               // Emerging
assert!(h.step(HexPhase::Dissolving).is_err());    // Error::Refused (ZXV_E_STATE)
let bad = h.forbid();                              // Rollback, forever
let log = QuarantineLog::new(&cap, 1024)?;         // needs Caps::ATTEST
let seq = log.append(bad, 7, 42, &digest32)?;
log.verify()?;
```

`Hexagram` is `Copy` with `&`, `|` and `!`; there is no `From<Hexagram>`
for `Truth` or `bool` (a compile-fail doc test checks it).

## Hardware emulation and hardware updates (ABI 1.4)

Module `zxv::hw` (types re-exported at the crate root). Profiles are plain
data; the matrix needs `Caps::HW_MATRIX`; regions and contract packages
need `Caps::HW_RECONF`; release keys and packages need `Caps::CRYPTO_SIGN`.
`Caps::ALL` keeps its 1.1 value, so use `Caps::ALL_1_4` for every bit.
New refusals map to `RefusedKind::{NoProvider, Dispute, Quarantined,
Rollback, Blocked, Policy}`; `ZXV_E_TARGET` is a usage error. Everything is
integers. See [HW_EMULATION.md](../docs/HW_EMULATION.md).

* `HwProfile` (ZHP-1): `probe_host`, `reference` (R1, 16 nodes),
  `present`, `encode`/`decode`, `digest`, `add_node`, `set_cap`/`cap`,
  `set_ext`/`ext` (opaque, at most `hw::EXT_MAX` bytes), `match_host`,
  `pair`.
* `HwMatrix`: starts with the standard engines (`hw::FN_SHA256`,
  `FN_KECCAK`, `FN_MAC`, `FN_GCD`, `FN_LOGIC64`, `FN_TENSOR`), each served
  by a proven SOFT implementation. Discover with `providers()` /
  `provider_info` / `find_provider` / `function_info`; constrain with
  `set_policy` (`HwPolicy::KEY_BEARING` is sticky and keeps work local);
  add your own implementations as closures with `add_provider`, prove them
  with `attest`, `call`, `shadow`, `memo`, `trust_key` + `apply_contract`,
  `log` / `log_entry`.
* `HwRelease`: `keygen` (an `HwReleaseKey` whose two secret halves are
  `SecretKey`s, wiped on drop) and `build` (header || payload ||
  ML-DSA-87 and SLH-DSA signatures; SLH-DSA takes seconds).
* `HwRegion`: a device you implement (`HwDevice`: load, readback,
  activate), `trust_key`, `stage`, `trial`, `commit`, `rollback`, `tick`,
  `info`, `on_event`, `log` / `log_entry` (records carry a `Hexagram` tag).

```rust
use zxv::{hw, Caps, Context, HwMatrix, HwProfile};

let r1 = HwProfile::reference()?;
let m = HwProfile::match_host(&HwProfile::probe_host()?, &r1)?;
let ctx = Context::new()?;
let cap = ctx.root_capability(1, None, Caps::ALL_1_4)?;
let mx = HwMatrix::new(&cap)?;
let digest = mx.call(hw::FN_SHA256, 0, b"abc")?;  // ba7816bf...
```

Callbacks (provider closures, `HwDevice` methods, event handlers) run on
the thread of the call that needs them. A panic is caught at the C
boundary and reported to the library as `ZXV_E_INTERNAL`; an `Err(e)`
becomes `e`'s status. Provider closures are `'static`; a device may borrow
(for example another matrix used as a SHA-256 oracle).

## ABI 1.5: treaties, content ids, coins, fees, hub, freight, Web 4, paradox

New capability bits: `Caps::AIPI` (store and publish AIPI blocks),
`Caps::MINT` (token wallets) and `Caps::PARADOX` (paradox books, policies,
holds, graphs); `Caps::ALL_1_5` is every bit. `zxv::features2()` reports
which groups were built (`Features2::TREATY` ... `Features2::PARADOX`).
New statuses and their classes: `ZXV_E_DENOM` and `ZXV_E_TREATY` are
`Error::Usage`; `ZXV_E_CID`, `CONSENT`, `ERASURE`, `PEG`, `LIMIT`,
`PARADOX_STEP` and `PARADOX_OWNER` are `Error::Refused` with
`RefusedKind::{Cid, Consent, Erasure, Peg, Limit, ParadoxStep,
ParadoxOwner}`.

Fixed-size byte structures are `Copy` value types you can compare with
`==` (`Cid`, `FreightHeader`, `ConsentToken`, `RepairProof`,
`ParadoxDraft`, `TokenHolding`, `FeeSplit`, the 40-byte peg message).
Indexed reads are iterators (`TreatyResult::legs`, `W4Manifest::tools`,
`ParadoxBook::registry` / `log_records`, `ParadoxHold::branches`,
`ParadoxGraph::nodes`, `coin::token_codes`). Handles tied to a context
(`AipiNode`, `TokenWallet`, `VHub`, `W4Agent`, `ParadoxBook`,
`ParadoxPolicy`, `ParadoxHold`, `ParadoxGraph`) borrow the capability they
were made with, use it on every gated call, fail closed when the context
halts, and cannot outlive it (a compile error). Every handle frees itself
on `Drop`. Handles that libzxv locks itself are `Send + Sync`; the others
(`FreightJoin`, `FreightOpsWriter`, `W4Agent`, `W4Directory`,
`W4Manifest`, `ConsentLog`, policy, hold, graph) are `Send` only and take
`&mut self` to change, so the borrow checker serializes them.

### Treaty

COBOL copybook treaties and canonical Sutra text: parse, emit, validate and
run NET or SETL settlement with PIC S9(18) arithmetic (`treaty::pic_add`
... `pic_div`). A refusal is a `TreatyError` carrying the `TreatyFault` and
its byte offset; it converts into `zxv::Error` for `?`.

```rust
use zxv::treaty::{Treaty, TreatyError};

let t = Treaty::parse_sutra("TREATY C USD SETL\nPARTY A 5000 3000 1/2\n\
                             PARTY B 3000 3000 1/2\nOWE A B 1200\nEND\n")?;
let rec = t.record()?;              // the 2542-byte copybook record
for leg in t.run()?.legs()? { println!("{leg:?}"); }   // InsufficientFunds if a party cannot pay
if let Err(TreatyError { fault, offset, .. }) = Treaty::parse_sutra("TREATY c USD SETL\n") {
    println!("{fault:?} at byte {offset}");             // Name at byte 7
}
```

### CID and AIPI

IPFS CIDs (`Cid::compute`, `unixfs`, `parse`, `text`, `info`, `to_v1`,
`verify`, `provider_key`; `Display` and `FromStr` use the Kubo text form)
and AIPI function, call and claim records (`AipiFunction`, `encode_call`,
`call_cid`, `AipiClaim`). An `AipiNode` (needs `Caps::AIPI`) is an offline
in-memory block store and planner: there is no network transport.

```rust
use zxv::{aipi::{self, Cid}, AipiNode, Caps, Context};

let c = Cid::compute(aipi::CODEC_RAW, b"abc")?;
println!("{c}");                                   // bafkreif2pall7dyb...
let ctx = Context::new()?;
let cap = ctx.root_capability(1, None, Caps::ALL_1_5)?;
let node = AipiNode::new(&cap, aipi::STORE_MIN, 64, None)?;
let id = node.put(b"zxv module bytes", false)?;
assert_eq!(node.get(&id)?, b"zxv module bytes");   // re-hashed before it is returned
```

### Coin and token octane

Fibonacci coin faces and Zeckendorf splits (`coin_face`, `coin_rung`,
`coin_split`, `coin_split_count`), swarm token tiers (`token_face`,
`token_tier`; a dense token is worth exactly its face: density carries no
premium, fee or extra allotment), `TokenHolding` (64 tier counts:
`value`, `compress`, `fuse`, `split`, `canonical`), the token prefix code
(`encode_token_codes`, `token_codes` iterator) and a `TokenWallet` (needs
`Caps::MINT`).

```rust
use zxv::{coin::{self, Octane, TokenHolding}, TokenWallet};

assert_eq!(coin::coin_split(100)?, vec![10, 5, 3]);   // 89 + 8 + 3
let h = TokenHolding::canonical(100, Octane::MIDGRADE)?;
let (value, pieces) = h.value()?;                     // (100, 3)
let w = TokenWallet::new(&cap, 1, Octane::PLAIN)?;
w.mint(100)?;
```

### Fee

The 0.08889% assurance fee and its 50/25/15/10 split, exact integers,
pure.

```rust
use zxv::fee;

assert_eq!(fee::assurance_fee(1125)?, 1);
let (f, rem) = fee::assurance_fee_carry(0, 100)?;  // (0, 888900): keep rem per account
let parts = fee::split_fee(10)?;                   // FeeSplit([6, 2, 1, 1])
```

### V-Bill hub

A demonstration hub with test currencies only (ISO codes are refused),
signed exact pegs, quotes and all-or-nothing swaps on its own in-memory
ledger. Every currency needs a limit rule (`add_limit`) before it can swap
(fail closed). Moving real money needs its owner's policy; this does not.

```rust
use zxv::{vhub::{self, VHub}, MlDsa87};

let dsa = MlDsa87::new(&cap);
let (issuer_pk, issuer_sk) = dsa.keygen()?;
let hub = VHub::new(&cap, None)?;
hub.add_currency(0, "ZTA", 2, &issuer_pk, 500_000, 10_000)?;
let msg = vhub::peg_message(0, 350, 1, 1)?;
hub.set_peg(0, 350, 1, 1, &dsa.sign(&issuer_sk, &msg, &[])?)?;  // Refused(Peg) when stale
```

### Freight

168 erasure-coded 21-byte rows per freight: any k rows rebuild the
payload. `freight::split` and `FreightJoin` carry larger payloads; op
streams (`FreightOpsWriter`, `ops_encode`) expand under a limit you set.
A CIDREF resolver is a closure called during `ops_expand_with`; a panic in
it is caught at the C boundary (never unwound through C) and the call
fails with `ZXV_E_INTERNAL`. No compression ratio is promised.

```rust
use zxv::freight::{self, FreightHeader};

let payload = b"hello freight".to_vec();
let h = FreightHeader::new(42, 10, 0, 0, &payload)?;   // k = 10
let packets = freight::encode(&h, &payload)?;          // 3528 bytes
assert_eq!(freight::decode(&h, &packets[21 * 100..])?, payload);  // rows 100..167 suffice
```

### Web 4

Agents with ML-DSA-65 keys that never leave their `W4Agent` handle (drop
wipes them; `Debug` shows ids only), signed cards and tool manifests, a
`W4Directory`, human `ConsentToken`s with a `ConsentLog`, and signed
envelopes (`seal`, `reply`, `verify_envelope`). Every call that needs the
time takes `now_ms`. Tools flagged money or PII need a consent token from
the human who owns the action.

```rust
use zxv::web4::{self, ConsentRequest, W4Agent, W4Manifest, W4Tool};

let now = 1_700_000_000_000;
let alice = W4Agent::new(&cap, None, "alice", None, now)?;
let human = W4Agent::new(&cap, None, "human", None, now)?;
let mut m = W4Manifest::new(1, now, now + 86_400_000)?;
m.add_tool(&W4Tool { name: "pay".into(), price_vfv: 150, rate_per_min: 60, burst: 10,
                     flags: web4::TOOL_MONEY, max_input: 256 })?;
m.sign(&alice)?;
let id = alice.info()?.agent_id;
let action = web4::action_digest("pay", &id, &[7; 32], 7, b"amount=100")?;
let token = web4::issue_consent(&cap, &human, &ConsentRequest { agent_id: id, action,
    scope: web4::CONSENT_MONEY, max_vfv: 1000, issued_ms: now, expires_ms: now + 600_000,
    nonce: None })?;
```

### Paradox

Classify a `Hexagram` into a `ParadoxClass` and run the fixed, logged
operator for it (`constructive`, `destructive`, `neutral`, `special`,
`draft` / `review`, `graph_pass`). `Refused` and `ProposalForOwner` are
outcomes, not errors; `graph_pass` returns `Refused(ParadoxStep)` when a
graph must escalate to its owner. Every decision is advisory: policy
changes outside published bounds go to the owner as a proposal.

```rust
use zxv::paradox::{ParadoxEvidence, ParadoxOutcome};
use zxv::{HexBase, HexPhase, HexPolarity, Hexagram, ParadoxBook, ParadoxPolicy};

let book = ParadoxBook::new(&cap, 64, 16)?;
let tag = Hexagram::new(HexBase::Both, HexPolarity::Neutral, HexPhase::Manifest);
let ev = ParadoxEvidence { pos0: 3, neg0: 1, pos1: 5, neg1: 1, stale: false };
let c = book.classify(tag, Some(&ev), None)?.class;    // constructive
let mut pol = ParadoxPolicy::new(&cap, &[0], &[100], &[50], 0)?;
assert_eq!(book.constructive(&mut pol, c, Some(&[60]), 5)?, ParadoxOutcome::Applied);
```

## Vino Embed (ABI 1.6)

The [`vino`] module lets an app or game take part in Vino without ever
holding anyone's value or keys. Two lanes never meet:

- **PLAY** (`VinoPlay`): a sandbox inside the app with its own play units,
  issuers, holders and Fibonacci-face vouchers, in process memory only.
  Play units are not money, cannot be converted into or moved to live
  value, and are lost on drop.
- **LIVE**: real Vino stays in the user's own ZXV wallet. The app builds a
  `PaymentRequest`; the wallet approves it and signs a receipt
  (`vino::sign_receipt`, the wallet's call with its own key); the app
  checks the receipt offline (`vino::verify_receipt`). The app never sees a
  balance, a key or a custody account.

A voucher is active on exactly one `Rail` (`Bearer` or `Ghost`) and can be
spent only on that rail (`RefusedKind::Rail`). An issuer may issue only
while `10 * backing >= 18 * outstanding` (`RefusedKind::Coverage`).
Redeeming retires a voucher and pays nothing out; there is no interest,
yield or return of any kind. `SpendMeter` counts what one device approved
per day against a daily cap (`RefusedKind::Limit`); it is a counter, not a
legal check.

New: `Caps::VINO` (play lane and meter; `Caps::ALL_1_6` is every bit),
`Features2::VINO`, `RefusedKind::{Rail, Coverage, Expired, Chance}` and
`ZXV_E_LANE` (USAGE). Requests (`[u8; 160]`), ids (`[u8; 32]`) and receipt
messages (`[u8; 88]`) are plain arrays; amounts, ids and times are `u64`.
`VinoPlay` and `SpendMeter` borrow their capability (they cannot outlive
it), are `Send + Sync`, and release on drop. Encoding, decoding, the
receipt message and verification are pure and need no capability.

Play-lane shop:

```rust
use zxv::vino::{PlayAccountKind, Rail, VinoPlay};
let cap = ctx.root_capability(1, None, Caps::VINO)?;
let play = VinoPlay::new(&cap)?;
let issuer = play.open(100, PlayAccountKind::Issuer)?;
let player = play.open(200, PlayAccountKind::Holder)?;
let shop = play.open(300, PlayAccountKind::Holder)?;
play.back(issuer, 18)?;                                // play faucet: faces up to 10
let coin = play.issue(issuer, player, 8, Rail::Bearer)?; // 13 would be RefusedKind::Coverage
play.transfer(coin, player, shop, Rail::Bearer)?;        // the player spends it
play.redeem(coin, shop)?;                                // retired; nothing is paid out
assert!(play.vouchers(shop)?.is_empty());
```

Live payment request, wallet receipt, offline verify:

```rust
use zxv::vino::{self, Lane, PaymentRequest, RequestFlags};
let req = PaymentRequest { lane: Lane::Live, flags: RequestFlags::NONE,
    merchant, nonce, amount: 1_234_567, created_at: now, expires_at: now + 600,
    memo: "Sword of Dawn".into() };
let (bytes, id) = req.encode()?;   // RefusedKind::Chance for a paid chance outcome on LIVE
// in the wallet, never the app:
let sig = vino::sign_receipt(&wallet_cap, &bytes, &wallet_sk, &wallet_pk, approved_at)?;
// back in the app, offline:
vino::verify_receipt(&bytes, &wallet_pk, approved_at, &sig, now)?; // VerificationFailed or Expired
```

`cargo run --example vino` runs both. Honest limits: the LIVE flow here is
only the app's half; the wallet posts the payment on its own ledger.
ML-DSA-87 is the reference implementation, not FIPS 140-3 validated.
Whether a deployment of Vino is store credit, a prepaid access product or
something else is a legal question pending counsel; nothing here decides
it. The raffle is a separate module.

[`vino`]: https://docs.rs/zxv/latest/zxv/vino/

## Honest limits

- **Least privilege, not a sandbox.** Capabilities stop mistakes, not
  hostile code in the same process: anyone can call
  `Context::root_capability` or use `zxv::sys` directly. Enforcement
  needs a process boundary.
- **Secrets.** `SecretKey` wipes its own buffer, but cannot wipe copies
  you made before handing bytes in, copies made by
  `export_bytes_unsafe`, memory swapped to disk, or core dumps. Memory is
  not locked (`mlock`). The crypto is not FIPS 140-3 validated.
- **Fatal is not uncatchable** with the default policy: a program can
  ignore an `Error::Fatal`; it just cannot make the context work again.
  Only `FatalPolicy::Abort` is truly terminal.
- **Async wake-ups** only come from calls made through this SDK's
  `Budgets`/`PhaseClock` handles (the C library has no phase listener, and
  the rmag listener is per handle). Waiting futures are woken by
  `release`, `set_limit`, `advance` and `cancel` on the same handle.
- **Budget callbacks** (`on_event`, `on_exhausted`) run synchronously
  inside the call that caused them; if one calls back into libzxv on the
  same thread, it can overwrite that call's last-error detail.
- **Not wrapped:** netting cycles, card issuing/authorization and VSS
  conformance checks (all `NOTIMPL` in this library build); use
  `zxv::sys` if you need them. Card check digits are wrapped.
- **LoRA** is declared by the ABI but not built: `Model::load_lora` returns
  `Refused(NotImplemented)` while `Features::LORA` is off.
- **No network transport**: the ledger is in-process, and nothing here is
  certified by any payment scheme.
- **ABI 1.5 groups** are offline: no network transport (AIPI nodes,
  freight and Web 4 envelopes are bytes you move yourself). The V-Bill
  hub uses test currencies only; real money and device policies need
  their owner. Freight promises no compression ratio. Token density
  carries no premium. Paradox outcomes are advisory and logged.
- **Streaming** runs generation on a scoped helper thread; `generate_with`
  runs on the calling thread and blocks it.
