# ZXV Rust SDK

Safe Rust bindings to `libzxv`, the stable C ABI of the ZXV platform
(`sdk/libzxv/include/zxv_api.h`, ABI 1.4). Two crates:

| Crate | What it is |
|---|---|
| `zxv-sys` | Raw `unsafe` bindings, generated by bindgen and checked in (`src/bindings.rs`), so a normal build needs no libclang. |
| `zxv` | The safe API you use. |

## Install

Build `libzxv` first (`make -C sdk/libzxv`), then depend on the crate:

```toml
[dependencies]
zxv = { path = "sdk/rust/zxv" }            # dynamic libzxv.so
# zxv = { path = "sdk/rust/zxv", features = ["static"] }   # link libzxv.a
```

`zxv-sys` finds the library in `ZXV_LIB_DIR`, else in `sdk/libzxv/build`.
With the default dynamic link your binary needs `libzxv.so` at run time:
use `LD_LIBRARY_PATH`, install it on the system path, add an rpath in your
own `build.rs` (`cargo:rustc-link-arg=-Wl,-rpath,<dir>`), or use the
`static` feature. This crate's own tests and examples get an rpath
automatically.

Regenerate the raw bindings after a header change (needs libclang):

```sh
LIBCLANG_PATH=/usr/lib/llvm-18/lib cargo build -p zxv-sys --features regenerate
```

## Quickstart

```rust
use zxv::{AccountKind, Caps, Context, Ledger};

fn main() -> zxv::Result<()> {
    let ctx = Context::new()?;                                  // one platform instance
    let root = ctx.root_capability(1, None, Caps::ALL)?;        // what you may do
    ctx.enable_currency_cap(&root, "NGN")?;
    let ledger = Ledger::new(&root);
    let bank = ledger.open_account("bank", "NGN", AccountKind::Issuer)?;
    let alice = ledger.open_account("alice", "NGN", AccountKind::Holder)?;
    ledger.post(bank, alice, 12_550, "NGN", "E2E-0001")?;     // exact minor units
    println!("{}", ledger.balance(alice)?.equity);              // 12550
    Ok(())
}
```

## Concepts in Rust terms

**Handles and lifetimes.** Every C handle is a Rust struct that frees it in
`Drop`. Children borrow their parents: `Capability<'c>` borrows its
`Context` (and an attenuated capability borrows its parent), `Session<'a>`
borrows its `Model`, its `Capability` and any bound `Budget`,
`DeferredEvent` borrows its `PhaseClock`. The C rule "destroy a child
before its parent" (R6) is enforced by the borrow checker; writing it the
other way round does not compile.

**Threads.** `Context`, `Capability`, `Model`, `Budgets`, `PhaseClock`,
`Swarm` and `Attestations` are `Send + Sync` (the C objects are
mutex-protected or immutable). `Session` and `iso20022::Message` are `Send`
but not `Sync`: one thread at a time, as the C ABI requires.

**Errors.** Every fallible call returns `zxv::Result<T>`. `zxv::Error` is an
enum by status class: `Usage` (your bug), `Refused(RefusedKind, _)` (handle
it: `CapabilityDenied`, `BudgetExhausted`, `InsufficientFunds`,
`VerificationFailed`, `NotImplemented`, ...), `Fatal` and `System`. Each
carries `status()`, `name()` and `detail()` (the library's last-error text;
never branch on it).

**Fail closed.** A FATAL status (a broken ledger invariant, or
`Context::halt`) halts the context in C: every later call returns
`ZXV_E_POISONED`. The Rust `Context` is also marked poisoned, and every
handle derived from it returns `Error::Fatal` without reaching the library.
`Context::with_fatal_policy(FatalPolicy::Abort)` instead prints the error
and calls `std::process::abort()`: the only form that cannot be caught.

**Capabilities.** Objects that make gated calls (`Ledger`, `Budgets`,
`PhaseClock`, `Swarm`, `Attestations`, `Ed25519`, `MlDsa87`, `MlKem1024`,
`StateChannel`, `Session`) hold a `&Capability` and pass it on every call.
Narrow with `cap.attenuate(Caps::LEDGER_READ)`; `revoke()` revokes all
descendants; an attestation other than `Truth::True` blocks the cap.

**Exact numbers.** No public function takes `f32`/`f64` except
`Rational::from_f64_exact`, which returns the double's exact value
(`0.1` is `3602879701896397/36028797018963968`) and rejects NaN/infinity.
`Rational` is a `Copy` value with `checked_add/sub/mul/div` returning
`Result`, exact `Ord`, `FromStr` (`"12.75"`, `"3/4"`) and `Display`. There
are no `+ - * /` operators, so overflow is always a `Result`. Sampling
parameters are `Rational`s, converted to Q16.16 by the library.

**Four-valued logic.** `Truth` is `Neither`, `True`, `False`, `Both`
(numbered 0..3 as the kernel numbers them). There is no `From<Truth> for
bool`; use `is_certainly_true()`, `to_bool(on_both, on_neither)` or
`require_true()`.

**Secrets.** `SecretKey` holds secret keys and shared secrets in one heap
allocation wiped with `zxv_secure_zero` on drop; `Debug` is redacted; the
only way out is `export_bytes_unsafe()`.

**Async.** `Budget::consume_async(amount)` returns a plain
`std::future::Future` that consumes now or waits until the budget is
replenished (a `release` or a larger `set_limit` through this SDK), then
retries; it fails immediately on an invalid amount. `PhaseClock::defer(tick)`
returns a `DeferredEvent` you `.await` (`IntoFuture`) or wait on with
`.cleared()`. They need no particular runtime: tokio, async-std,
`futures::executor::block_on`, or your own. Cancel by dropping the
future; add timeouts with your runtime. Drive the clock manually with
`advance(n)` or in real time with `run_realtime(ticks_per_second, &stop)` on
a thread you own.

**Generation.** `Session::generate` (all at once), `generate_with` (a
callback per token; return `false` to stop) and `stream` (an `Iterator` of
tokens inside a closure; dropping it stops generation). The same seed and
inputs give the same tokens on every machine.

## Capabilities on every gated call (ABI 1.2)

Every gated operation takes a `Capability`, and the SDK calls the
capability-gated `zxv_*_cap` form of the C ABI:

| Call | Needs |
|---|---|
| `Context::enable_currency_cap`, `enable_currency_with_minor_cap`, `register_private_currency_cap` | `LEDGER_POST` |
| `Ledger::open_account`, `post` | `LEDGER_POST` |
| `Ledger::balance`, `account`, `account_count`, `journal`; `Capability::new_message` | `LEDGER_READ` |
| `Budgets::new`, `PhaseClock::new`, `Attestations::new`, `Swarm::new` | `BUDGET`, `PHASE`, `ATTEST`, `SWARM` |

A capability of another context is refused with `ZXV_E_CAP`
(`is_capability_denied()`). A message borrows the capability it was made
with and the library re-checks it on every call. The 1.0 forms
`Context::enable_currency`, `enable_currency_with_minor`,
`register_private_currency` and `new_message` still work but are
`#[deprecated(since = "1.2.0")]`.

## The hexagram tag (ABI 1.3)

A `Hexagram` tags one unit of work with a four-valued base, the polarity
of its evidence (entropic, neutral, forbidden, negentropic) and its phase
(potential -> emerging -> manifest -> dissolving), packed into one byte
0..63. Its action is proceed, wait, refuse, escalate or rollback. Every rule
comes from libzxv and is tested against `vectors.json` key `hex`.
Forbidden is absorbing, a phase moves one step at a time, and the base is
**not** numbered like `Truth` (TRUE is base 3 but Truth 1): convert only
with the explicit `to_truth()` / `Hexagram::from_truth(...)`. Combining BOTH with NEITHER follows
the `Truth` tables (AND gives NEITHER, OR gives BOTH); those two results
are pending an owner decision. A `QuarantineLog` (needs the ATTEST
capability) records forbidden work in a SHA-256 hash chain; when it is
full, append is refused with `ZXV_E_CAPACITY` and you must halt the
context. See [ABI.md, Changes in 1.3](../docs/ABI.md#changes-in-13).

```rust
use zxv::{HexAction, HexBase, HexPhase, HexPolarity, Hexagram, QuarantineLog};

let h = Hexagram::new(HexBase::True, HexPolarity::Negentropic, HexPhase::Potential);
assert_eq!(h.action(), HexAction::Proceed);
let h = h.advance();                               // Emerging
assert!(h.step(HexPhase::Dissolving).is_err());    // Error::Refused (ZXV_E_STATE)
let bad = h.forbid();                              // Rollback, forever
let log = QuarantineLog::new(&cap, 1024)?;         // needs Caps::ATTEST
let seq = log.append(bad, 7, 42, &digest32)?;
log.verify()?;
```

`Hexagram` is `Copy` with `&`, `|` and `!`; there is no `From<Hexagram>`
for `Truth` or `bool` (a compile-fail doc test checks it).

## Hardware emulation and hardware updates (ABI 1.4)

Module `zxv::hw` (types re-exported at the crate root). Profiles are plain
data; the matrix needs `Caps::HW_MATRIX`; regions and contract packages
need `Caps::HW_RECONF`; release keys and packages need `Caps::CRYPTO_SIGN`.
`Caps::ALL` keeps its 1.1 value, so use `Caps::ALL_1_4` for every bit.
New refusals map to `RefusedKind::{NoProvider, Dispute, Quarantined,
Rollback, Blocked, Policy}`; `ZXV_E_TARGET` is a usage error. Everything is
integers. See [HW_EMULATION.md](../docs/HW_EMULATION.md).

* `HwProfile` (ZHP-1): `probe_host`, `reference` (R1, 16 nodes),
  `present`, `encode`/`decode`, `digest`, `add_node`, `set_cap`/`cap`,
  `set_ext`/`ext` (opaque, at most `hw::EXT_MAX` bytes), `match_host`,
  `pair`.
* `HwMatrix`: starts with the standard engines (`hw::FN_SHA256`,
  `FN_KECCAK`, `FN_MAC`, `FN_GCD`, `FN_LOGIC64`, `FN_TENSOR`), each served
  by a proven SOFT implementation. Discover with `providers()` /
  `provider_info` / `find_provider` / `function_info`; constrain with
  `set_policy` (`HwPolicy::KEY_BEARING` is sticky and keeps work local);
  add your own implementations as closures with `add_provider`, prove them
  with `attest`, `call`, `shadow`, `memo`, `trust_key` + `apply_contract`,
  `log` / `log_entry`.
* `HwRelease`: `keygen` (an `HwReleaseKey` whose two secret halves are
  `SecretKey`s, wiped on drop) and `build` (header || payload ||
  ML-DSA-87 and SLH-DSA signatures; SLH-DSA takes seconds).
* `HwRegion`: a device you implement (`HwDevice`: load, readback,
  activate), `trust_key`, `stage`, `trial`, `commit`, `rollback`, `tick`,
  `info`, `on_event`, `log` / `log_entry` (records carry a `Hexagram` tag).

```rust
use zxv::{hw, Caps, Context, HwMatrix, HwProfile};

let r1 = HwProfile::reference()?;
let m = HwProfile::match_host(&HwProfile::probe_host()?, &r1)?;
let ctx = Context::new()?;
let cap = ctx.root_capability(1, None, Caps::ALL_1_4)?;
let mx = HwMatrix::new(&cap)?;
let digest = mx.call(hw::FN_SHA256, 0, b"abc")?;  // ba7816bf...
```

Callbacks (provider closures, `HwDevice` methods, event handlers) run on
the thread of the call that needs them. A panic is caught at the C
boundary and reported to the library as `ZXV_E_INTERNAL`; an `Err(e)`
becomes `e`'s status. Provider closures are `'static`; a device may borrow
(for example another matrix used as a SHA-256 oracle).

| Area | Types | Key calls |

| Capability | `Capability`, `Caps` | `attenuate`, `revoke`, `set_attestation`, `check`, `info`, `new_message` |

| Ledger | `Ledger`, `AccountId`, `Balance` | `open_account`, `post`, `balance`, `check`, `account`, `account_count`, `journal` |
| ISO data | `iso4217`, `iso20022::Message` | `by_alpha`, `by_numeric`, `set_text`, `set_amount`, `render` |

| Phase | `PhaseClock`, `DeferredEvent` | `advance`, `admit`, `defer`/`until_tick`/`after`, `.await`, `run_realtime` |

| Escape hatch | `zxv::sys`, `as_raw()` | raw calls for anything not wrapped |

## Tests

```sh
cd sdk/rust
cargo test            # conformance vectors + behaviour + doc tests
cargo doc --no-deps
```

`tests/hw.rs` mirrors `test_zxv_abi14.c` (ABI 1.4): R1, profiles, the standard
engines, placement (MAC never goes REMOTE), proof, failover, shadow, memo,
contracts, and a full stage / trial / commit / quarantine cycle with events,
the audit log and fail-closed when it fills (three SLH-DSA signings, ~5 s).

`tests/hexagram.rs` checks the `hex` key (ABI 1.3): every tag, the logic, step and
set tables, the Truth mapping and the quarantine chain.

`tests/conformance.rs` checks every other key of `sdk/conformance/vectors.json`
(status classes, rationals, IEEE-754 boundary, Q16, lpres tables, UBH-168
frames byte for byte in pure Rust and in C, hashes, Ed25519, ML-DSA-87 and
ML-KEM-1024 digests, swarm allotments, greedy and seeded generation, EVM
encoding). `tests/behaviour.rs` covers the fatal path (`halt`, both
policies), capability denial and revocation, budget exhaustion,
`consume_async` on two executors, phase deferral with both drivers,
streaming, budget-bound generation and the ledger.

## Honest limits

- **Least privilege, not a sandbox.** Capabilities stop mistakes, not
  hostile code in the same process: anyone can call
  `Context::root_capability` or use `zxv::sys` directly. Enforcement
  needs a process boundary.
- **Secrets.** `SecretKey` wipes its own buffer, but cannot wipe copies
  you made before handing bytes in, copies made by
  `export_bytes_unsafe`, memory swapped to disk, or core dumps. Memory is
  not locked (`mlock`). The crypto is not FIPS 140-3 validated.
- **Fatal is not uncatchable** with the default policy: a program can
  ignore an `Error::Fatal`; it just cannot make the context work again.
  Only `FatalPolicy::Abort` is truly terminal.
- **Async wake-ups** only come from calls made through this SDK's
  `Budgets`/`PhaseClock` handles (the C library has no phase listener, and
  the rmag listener is per handle). Waiting futures are woken by
  `release`, `set_limit`, `advance` and `cancel` on the same handle.
- **Budget callbacks** (`on_event`, `on_exhausted`) run synchronously
  inside the call that caused them; if one calls back into libzxv on the
  same thread, it can overwrite that call's last-error detail.
- **Not wrapped:** netting cycles, card issuing/authorization and VSS
  conformance checks (all `NOTIMPL` in this library build); use
  `zxv::sys` if you need them. Card check digits are wrapped.
- **LoRA** is declared by the ABI but not built: `Model::load_lora` returns
  `Refused(NotImplemented)` while `Features::LORA` is off.
- **No network transport**: the ledger is in-process, and nothing here is
  certified by any payment scheme.
- **Streaming** runs generation on a scoped helper thread; `generate_with`
  runs on the calling thread and blocks it.
